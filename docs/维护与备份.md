# 更新、备份与恢复

## 更新

1. 等待保存完成，关闭面板服务和所有正在录入的 WorkBuddy 任务。
2. 将整个 data 目录备份到本机另一个安全位置，包含 JSON、附件与备份。
3. 将新版下载到新目录，按其说明检查数据版本兼容性。本版 schemaVersion=1；不做自动破坏性迁移。
4. 默认数据目录使用者：将旧 data 复制到新项目内；VITALS_DATA_DIR 使用者：确保新服务和 CLI 使用相同环境变量。
5. 执行 tools/setup.py 和 --doctor，检查修订号与记录数，再切换 WorkBuddy 工作空间。

不要删除后重新初始化来“修复”档案，不将 templates/demo-data.json 覆盖 health-data.json。对现有 Git 安装，确认 data 已被忽略且没有被跟踪后再更新，不运行 git clean -fdx。

程序和 .codebuddy 技能可能更新，data 及本机 WorkBuddy 会话不应被新版本覆盖。跨设备复制时不要让两台电脑同时改同一份通过网盘同步的文件，本项目锁仅保证同一台本地文件系统的并发。

## 备份与恢复

每次成功写入前创建 JSON 备份，保留最近 80 份。原图保存在 data/attachments，不在每次 JSON 快照内重复复制。完整备份需要复制整个 data。

恢复前停止服务与录入，先备份当前 data。选择正确时间的 data/backups/health-data-*.json，检查格式后复制为 data/health-data.json，再运行 tools/setup.py 同步 JS 副本，运行 --doctor 检查。恢复旧 JSON 可能引用已清理的图片，因此不能只备份 JSON 后删除所有附件。

## 保存冲突或失败

浏览器页面打开后，CLI 或另一窗口可能更新档案。旧页面保存收到冲突时，会保留当前页面未保存内容并阻止继续覆盖。先到“数据源”导出当前未保存 JSON，刷新读取最新数据，再通过 CLI 的 list/update 合并需要的改动。不要把旧导出整份覆盖回去。

一般网络失败可点击侧栏“保存失败”重试；未保存状态下关闭页面会触发浏览器提醒。只有“已保存”或 CLI 成功回执代表落盘。

## 附件与彻底删除

从列表删除一条记录不删除历史备份、原图或 WorkBuddy 中的消息。这是防误删设计。需要清除敏感内容时，先确认所有保留记录的 photo 引用，停止程序，清理不再需要的附件和包含该内容的历史快照；WorkBuddy 中的数据另外按其设置管理。清理不可恢复，应由用户明确指定范围。

## 发布

只发布本公开版目录，不能发布其上级个人项目。使用 tools/package_release.py 生成白名单 ZIP，再审阅包内文件和文档。运行时 data、.workbuddy、.git、缓存、日志均不包含在 ZIP 中。没有配置实际 GitHub 仓库地址时，README 的安装指令让用户另附仓库地址，不编造下载链接。
