# 数据字典

所有数据存在 `data/health-data.json`。顶层结构：

| 键 | 说明 |
|---|---|
| `schemaVersion` | 结构版本，当前 `1` |
| `meta` | 创建/更新时间、时区、修订号 |
| `profile` | 身体基线与目标 |
| `sources` | 三个数据源的接入状态与最近同步时间 |
| `bodyMetrics[]` | 体成分记录（体脂秤） |
| `dailyActivity[]` | 每日活动记录（手环），一天一条 |
| `meals[]` | 餐次记录，一餐一条 |
| `workouts[]` | 训练记录，一次一条 |
| `supplements[]` | 补剂记录，一次一条 |
| `journal[]` | 自由文本备注（预留） |
| `imports[]` | 导入历史 |

## profile

```json
{
  "sex": "male",
  "birthDate": "1993-04-12",
  "heightCm": 176,
  "activityFactor": 1.375,
  "bmrMode": "mifflin",
  "goal": {
    "type": "fat_loss",
    "targetWeightKg": 70,
    "targetBodyFatPct": 16,
    "weeklyRateKg": 0.5,
    "proteinPerKg": 1.8
  },
  "targets": { "kcal": null, "proteinG": null, "fatG": null, "carbG": null,
               "fiberG": 30, "steps": 9000, "sleepMin": 450 }
}
```

- `bmrMode`：`mifflin` 用公式；`scale` 直接采用体脂秤的 `bmrKcal`。
- `goal.type`：`record_only`（默认，仅记录，不自动设置营养目标）/ `fat_loss` / `maintain` / `muscle_gain`。
- `targets` 中的 `null` 表示自动计算；填了数字就以你填的为准（覆盖自动推算）。

## bodyMetrics

```json
{
  "id": "bm_...", "date": "2026-10-18", "measureMode": "fasting",
  "ts": "2026-10-18T07:12:00+08:00",
  "weightKg": 74.7, "bmi": 24.1, "bodyFatPct": 20.7, "muscleKg": 33.2,
  "waterPct": 51.2, "visceralFat": 12, "boneKg": 2.82, "bmrKcal": 1529,
  "proteinPct": 19.6, "bodyAge": null, "source": "xiaomi_scale", "note": "Zepp 身体得分 59 · 偏胖型"
}
```

`source` 取值：`xiaomi_scale`（体脂秤/导入）、`manual`（手填）。

`measureMode` 取值：`fasting`（晨起空腹）、`bedtime`（睡前）。**缺省按 `fasting` 处理。**

口径提醒：

- **`measureMode` 是防假信号的关键字段。** 晨起空腹和睡前是同一个人在不同含水量下的两次读数，一晚差 1–2 kg 属于水和糖原，不是脂肪。因此：趋势图、KPI 的「N 天变化」、目标达成预估**只取 `fasting` 序列**；`bedtime` 记录保留在表里供参考，但永不参与跨时段比较。
- 同一天同一来源的同一时段只保留最新一条（重复称重即覆盖）；同一天的晨起与睡前各存一条，互不覆盖。
- `muscleKg` 是**体脂秤口径**的肌肉量，即 `体重 − 脂肪 − 骨量`（Zepp Life / 小米秤都这么算），**不是骨骼肌量**。别拿它和"骨骼肌 34 kg"这类数值比。校验方法：`体重 × (1 − 体脂%) − 骨量` 应当近似等于 `muscleKg`。
- `proteinPct` 是体成分中的蛋白质占比（常见 16–20%），不是蛋白质摄入量。
- `visceralFat` 单位为等级：<10 标准，10–14 偏高，≥15 高。
- `bmrKcal` 是秤的估算值（生物电阻抗），通常比 Mifflin 公式低 5–10%；`profile.bmrMode` 决定面板用哪个。

## dailyActivity

```json
{
  "date": "2026-10-18", "steps": 9200, "distanceKm": 6.6,
  "activeKcal": 420, "totalKcal": 2450,
  "restingHr": 58, "hrAvg": 72, "hrMax": 142, "hrvMs": 46, "spo2": 96,
  "sleepMin": 445, "deepSleepMin": 96, "remSleepMin": 104,
  "lightSleepMin": 240, "awakeMin": 12, "sleepScore": 78,
  "standHours": 9, "source": "xiaomi_band"
}
```

一天只保留一条，重复导入按 `date` 覆盖。

## meals

```json
{
  "id": "ml_...", "date": "2026-10-18", "ts": "2026-10-18T12:30:00+08:00",
  "slot": "lunch",
  "title": "鸡胸肉饭 + 西兰花",
  "items": [
    { "name": "米饭（熟）", "amount": "180 g", "kcal": 209,
      "proteinG": 4.7, "fatG": 0.5, "carbG": 46.6, "fiberG": 0.5 }
  ],
  "totals": { "kcal": 508, "proteinG": 55.4, "fatG": 6.5, "carbG": 57.1, "fiberG": 4.4 },
  "confidence": "estimated",
  "source": "conversation",
  "photo": null, "note": ""
}
```

- `slot`：`breakfast` / `lunch` / `dinner` / `snack`。
- `confidence`：`estimated`（照片/目测估算）或 `measured`（称重/包装标签）。
- `totals` 是 `items` 的汇总，单独存一份便于快速统计；改 `items` 时要同步改 `totals`（`tools/log.py` 会自动算）。

## workouts

```json
{
  "id": "wk_...", "date": "2026-10-18", "ts": "2026-10-18T20:20:00+08:00",
  "type": "pushup", "typeLabel": "俯卧撑",
  "durationMin": 12, "kcal": 82, "intensity": "moderate",
  "volume": { "sets": [20,20,20,20,20], "totalReps": 100 },
  "distanceKm": null, "avgHr": 130,
  "source": "conversation", "note": ""
}
```

`type` 可选值：`pushup` `squat` `plank` `basketball` `swimming` `running` `cycling` `strength` `walking` `badminton` `jumprope` `rowing` `yoga` `hiking` `football` `other`。
自重项目填 `volume`，有氧项目填 `distanceKm`，都可留空。

## supplements

```json
{
  "id": "sp_...", "date": "2026-10-18", "ts": "2026-10-18T20:30:00+08:00",
  "name": "乳清蛋白", "dose": "30 g", "timing": "训练后",
  "nutrients": { "kcal": 118, "proteinG": 24.0, "fatG": 1.2, "carbG": 2.4 },
  "source": "conversation", "note": ""
}
```

`nutrients` 会计入全天摄入（蛋白粉这类有热量的补剂不应被漏掉）；维生素、矿物质填 0 即可。

## 派生指标（不存盘，打开面板时实时算）

| 指标 | 公式 |
|---|---|
| 年龄 | 由 `birthDate` 精确到日计算 |
| BMI | `体重 / (身高/100)²` |
| BMR | Mifflin-St Jeor，或体脂秤读数 |
| TDEE | `BMR × activityFactor` |
| 每日缺口 | `weeklyRateKg × 7700 / 7` |
| 目标热量 | `TDEE − 缺口` |
| 蛋白目标 | `体重 × proteinPerKg` |
| 脂肪目标 | `目标热量 × 27% / 9` |
| 碳水目标 | `(目标热量 − 蛋白×4 − 脂肪×9) / 4` |
| 每日消耗 | 手环 `totalKcal`；缺失时 `TDEE + 训练消耗 × 0.85` |
| 达成日期 | 近 3 周体重线性回归斜率 → `剩余体重 / 每周速率` |


## 公开版补充

运行时文件由 templates/empty-data.json 初始化；模板不含个人性别、生日或预设减脂目标。使用 VITALS_DATA_DIR 时以该目录为数据根。meta.revision 由共享存储递增，浏览器提交旧修订会收到 409。

record/update 返回的记录含稳定 id、sourceKey、createdAt、updatedAt；photo 是相对数据根的 attachments/摘要.扩展名。补剂、运动等未知值可省略；体重录入必须指定 measureMode。对话入口详见 对话录入.md。

营养合计由 CLI 从 items 重算。CLI 的 update 对 items 整组替换，调用方必须保留未修改食物。body 同日、同源、同时段覆盖；activity 按日期合并提供的字段，保留未提供的字段。删除不清理原图或快照。

历史“每日消耗”回退使用当前基线估算，不代表那天手环实测；目标达成日期只来自足够的同口径体重趋势，不由设定的每周目标速率承诺。
