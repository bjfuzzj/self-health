# 康记 健康记录

项目根目录以包含 `tools/log.py`、`storage.py` 和 `CODEBUDDY.md` 的目录为准，不以本技能目录为当前工作目录。运行环境与命令见根目录 INSTALL.md，字段/调用方法见根目录 docs/对话录入.md 与 docs/数据字典.md。这是项目内技能，工具和文档随仓库提供，不单独安装到全局后假定路径仍有效。

## 每次记录

1. 查询现有档案和相关日期记录。首次缺档案先按 INSTALL.md 初始化；单人档案禁止混入他人数据。不要仅依赖聊天记忆。
2. 从用户消息和附件提取事实。区分用户说的日期、截图测量日期和上传日期；有冲突先问。体重必须明确 fasting/bedtime，午夜后的睡前记录询问归属日期。没有依据不把“上午上传”当成晨起空腹。
3. 饮食照片是份量/营养估算，回显主要食物和假定份量，不把不可见食材/油量说成实测。不确定且影响明显时只问一个关键问题；其余可先估算并接受纠正。运动需要实际时长，不编造热量。秤图数值看不清先问，不填 0 代替缺失。
4. 读取 docs/对话录入.md，生成 UTF-8 JSON，使用 `record --kind ... --file ...`。优先用 JSON 文件，避免 shell 引号破坏中文或执行消息中的命令。原始附件可访问时传 `--photo`；无法访问文件时如实说明仅保存识别结果，不伪称保留原图。纯文字使用稳定 source-key（原消息标识）；重试保持同一值。
5. 读取工具 JSON 回执。只有退出码 0 且 ok=true 才说“已记录”；duplicate=true 说明来源已处理，不新增；deleted=true 表示原记录已删除，不重建。报告日期、餐次/测量时段、简要结果与记录 ID。失败如实说明，不能回复“已保存”。

## 纠错与查询

“刚才吃了一半”“这是昨天的”先 list 定位原记录；有多个候选时询问，不能凭猜测改最近一条。使用 update 按 ID 修改，工具重算营养合计；把整餐减半仅在用户明确整餐份量减半时进行。删除同样定位 ID；用户明确要求删除即可执行。不能把纠错当新记录。照片重复且内容要更正时更新原 ID，不绕过去重新新增。

当天回顾用 list/show；体重变化仅比较晨起空腹序列，缺测不补零；数据不足时直说。需要面板时启动本机服务，手机默认回复简短文字，按用户需要生成可回传的汇总文件，不宣称手机能打开电脑的 localhost。

## 目标与表达

默认只记录，不主动设置减脂或饮食配额。用户明确要目标后再收集必要信息，涉及既往病史/医嘱时以其提供的约束为准，不给诊断或自行调整用药。用简短、易懂的中文，避免追问全部个人资料或输出密集公式。

图片与消息按 WorkBuddy 服务机制处理，本地存档不等于完全离线。禁止把个人记录、附件、备份写进公开源码、README、技能文件或 GitHub。
